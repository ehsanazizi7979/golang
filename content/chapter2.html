2.2 · Web application basics

Three components make a web application: a handler (think: controller — runs logic and writes headers and a body), a router (Go calls it a servemux; it maps URL patterns to handlers) and a web server. In Go the server is part of your program — no Nginx or Apache required.

File: main.gogo
package main

import (
    "log"
    "net/http"
)

// Define a home handler function which writes a byte slice containing
// "Hello from Snippetbox" as the response body.
func home(w http.ResponseWriter, r *http.Request) {
    w.Write([]byte("Hello from Snippetbox"))
}

func main() {
    // Use the http.NewServeMux() function to initialize a new servemux, then
    // register the home function as the handler for the "/" URL pattern.
    mux := http.NewServeMux()
    mux.HandleFunc("/", home)

    // Use the http.ListenAndServe() function to start a new web server. We pass in
    // two parameters: the TCP network address to listen on (in this case ":4000")
    // and the servemux we just created. If http.ListenAndServe() returns an error
    // we use the log.Fatal() function to log the error message and exit. Note
    // that any error returned by http.ListenAndServe() is always non-nil.
    log.Print("Starting server on :4000")
    err := http.ListenAndServe(":4000", mux)
    log.Fatal(err)
}

Important. Go’s servemux treats the pattern "/" as a catch-all, so /foo returns the same page. Stop the server with Ctrl+c. The address format for http.ListenAndServe() is "host:port"; omitting the host listens on every interface.

One route is not much of an app, so two more are registered — the table the book has just introduced:

File: main.gogo
// Add a snippetView handler function.
func snippetView(w http.ResponseWriter, r *http.Request) {
    w.Write([]byte("Display a specific snippet..."))
}

// Add a snippetCreate handler function.
func snippetCreate(w http.ResponseWriter, r *http.Request) {
    w.Write([]byte("Create a new snippet..."))
}

func main() {
    mux := http.NewServeMux()
    mux.HandleFunc("/", home)
    mux.HandleFunc("/snippet/view", snippetView)
    mux.HandleFunc("/snippet/create", snippetCreate)

    log.Print("Starting server on :4000")
    err := http.ListenAndServe(":4000", mux)
    log.Fatal(err)
}

Fixed paths vs. subtree paths

Patterns without a trailing slash are fixed paths — matched only on an exact URL match. Patterns with a trailing slash are subtree paths — matched when the start of the URL matches, as if a wildcard sat at the end ("/**", "/static/**"). That is precisely why "/" behaves as a catch-all: it means “one slash, then anything or nothing”.

Go won’t let you change that behaviour, so the fix lives in the handler: check r.URL.Path and return http.NotFound() before writing anything.

File: main.gogo
func home(w http.ResponseWriter, r *http.Request) {
    // Check if the current request URL path exactly matches "/". If it doesn't, use
    // the http.NotFound() function to send a 404 response to the client.
    // Importantly, we then return from the handler. If we don't return the handler
    // would keep executing and also write the "Hello from SnippetBox" message.
    if r.URL.Path != "/" {
        http.NotFound(w, r)
        return
    }
    w.Write([]byte("Hello from Snippetbox"))
}

The DefaultServeMux

http.HandleFunc() registers routes without an explicit servemux, using a package-level global:

From the Go sourcego
var DefaultServeMux = NewServeMux()

The book advises against it for production: because it is global, any imported third-party package can register a route on it — and a compromised dependency could expose a malicious handler. Use a locally scoped servemux.

Additional information. Longer patterns always win, so registration order is irrelevant. Paths are sanitised (/foo/bar/..//baz → 301 to /foo/baz). A request for a registered subtree path without its trailing slash gets a 301 with the slash added. Patterns may include host names ("foo.example.org/"), which are checked before non-host patterns. And the servemux is deliberately lightweight: no method-based routing, no variables in URLs, no regexp — third-party routers cover those.

2.4 · Customizing HTTP headers

/snippet/create becomes a POST-only route. Later it will write to a database — a non-idempotent action — so HTTP good practice says restrict it now.

MethodPatternHandlerAction
ANY/homeDisplay the home page
ANY/snippet/viewsnippetViewDisplay a specific snippet
POST/snippet/createsnippetCreateCreate a new snippet

The first version sends the status code explicitly. Two nuances matter: w.WriteHeader() can only be called once, and if you don’t call it at all the first w.Write() sends 200 OK automatically — so a non-200 status must be written before any body.

File: main.go — first attemptgo
func snippetCreate(w http.ResponseWriter, r *http.Request) {
    if r.Method != "POST" {
        w.WriteHeader(405)
        w.Write([]byte("Method Not Allowed"))
        return
    }
    w.Write([]byte("Create a new snippet..."))
}

Method Not Allowed

Then the Allow header is added — a hint to clients about which methods the URL supports — followed by the http.Error() shortcut, which sets the status and body for us, and finally the net/http constants, which remove the typos waiting inside "POST" and 405. That last version is the finished handler:

File: main.go — final versiongo
func snippetCreate(w http.ResponseWriter, r *http.Request) {
    if r.Method != http.MethodPost {
        w.Header().Set("Allow", http.MethodPost)
        http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
        return
    }
    w.Write([]byte("Create a new snippet..."))
}
Terminal — with the Allow headershell
$ curl -i -X PUT http://localhost:4000/snippet/create
HTTP/1.1 405 Method Not Allowed

Date: Sat, 29 Jan 2022 10:29:12 GMT
Content-Length: 18
Content-Type: text/plain; charset=utf-8

Method Not Allowed

Important. Changing the header map after WriteHeader() or Write() has no effect — all headers must be set first.

Header mechanics from the additional information. Go sets Date, Content-Length and Content-Type itself; the content type comes from http.DetectContentType(), which cannot tell JSON from plain text, so JSON needs an explicit w.Header().Set("Content-Type", "application/json"). The map supports Set/Add/Del/Get/Values; names are canonicalised (case-insensitive) unless you write to the underlying map[string][]string directly — which is also the only way to suppress a system header, by setting it to nil.

Header map operationsgo
// Set a new cache-control header. If an existing "Cache-Control" header exists
// it will be overwritten.
w.Header().Set("Cache-Control", "public, max-age=31536000")

// In contrast, the Add() method appends a new "Cache-Control" header and can
// be called multiple times.
w.Header().Add("Cache-Control", "public")
w.Header().Add("Cache-Control", "max-age=31536000")

// Delete all values for the "Cache-Control" header.
w.Header().Del("Cache-Control")

// Retrieve the first value for the "Cache-Control" header.
w.Header().Get("Cache-Control")

// Retrieve a slice of all values for the "Cache-Control" header.
w.Header().Values("Cache-Control")

// Suppress a system-generated header.
w.Header()["Date"] = nil

2.5 · URL query strings

snippetView learns to accept ?id=1. The value is untrusted user input, so it is converted with strconv.Atoi() and validated to be a positive integer; anything else gets a 404.

File: main.gogo
import (
    "fmt" // New import
    "log"
    "net/http"
    "strconv" // New import
)

func snippetView(w http.ResponseWriter, r *http.Request) {
    // Extract the value of the id parameter from the query string and try to
    // convert it to an integer using the strconv.Atoi() function. If it can't
    // be converted to an integer, or the value is less than 1, we return a 404 page
    // not found response.
    id, err := strconv.Atoi(r.URL.Query().Get("id"))
    if err != nil || id < 1 {
        http.NotFound(w, r)
        return
    }

    // Use the fmt.Fprintf() function to interpolate the id value with our response
    // and write it to the http.ResponseWriter.
    fmt.Fprintf(w, "Display a specific snippet with ID %d...", id)
}

Why fmt.Fprintf(w, …) compiles. It wants an io.Writer…

io.Writergo
func Fprintf(w io.Writer, format string, a ...any) (n int, err error)

…yet an http.ResponseWriter is accepted, because it satisfies the interface by having a Write() method. In practice: anywhere you see an io.Writer, you can pass the response writer, and whatever is written becomes the response body.

2.6 · Project structure and organization

There is no single correct layout for Go web apps. The advice: don’t over-complicate; add structure only when it is demonstrably needed. This project follows a widely used outline.

Terminalshell
$ cd $HOME/code/snippetbox
$ rm main.go
$ mkdir -p cmd/web internal ui/html ui/static
$ touch cmd/web/main.go
$ touch cmd/web/handlers.go

Two benefits: Go and non-Go assets are cleanly separated (the root stays free for UI files, makefiles and module definitions), and the layout scales — a future CLI would sit at cmd/cli and import everything under internal. Note that internal is special in Go: packages beneath it can only be imported by code inside the parent of internal — that is, only by this project.

Note. .tmpl means nothing to Go — it just makes template files recognisable. .html or .tmpl.html work too, the latter helping editors with syntax highlighting.

File: cmd/web/handlers.go — rendering itgo
func home(w http.ResponseWriter, r *http.Request) {
    if r.URL.Path != "/" {
        http.NotFound(w, r)
        return
    }

    // Use the template.ParseFiles() function to read the template file into a
    // template set. If there's an error, we log the detailed error message and use
    // the http.Error() function to send a generic 500 Internal Server Error
    // response to the user.
    ts, err := template.ParseFiles("./ui/html/pages/home.tmpl")
    if err != nil {
        log.Print(err.Error())
        http.Error(w, "Internal Server Error", 500)
        return
    }

    // We then use the Execute() method on the template set to write the
    // template content as the response body. The last parameter to Execute()
    // represents any dynamic data that we want to pass in, which for now we'll
    // leave as nil.
    err = ts.Execute(w, nil)
    if err != nil {
        log.Print(err.Error())
        http.Error(w, "Internal Server Error", 500)
    }
}

The template set now holds three named templates — base, title and main — and ExecuteTemplate(w, "base", nil) renders the composition.

Reusable fragments go in their own files. The navigation bar becomes ui/html/partials/nav.tmpl, invoked with {{template "nav" .}} from the base template and added to the files slice.

2.8 · Serving static files

CSS, images and a little JavaScript arrive in ui/static, then http.FileServer serves them. Because the file server strips the leading slash and looks up the remainder inside the given directory, the /static prefix must be removed first — http.StripPrefix() does exactly that.

Terminalshell
$ curl https://www.alexedwards.net/static/sb-v2.tar.gz | tar -xvz -C ./ui/static/
File: cmd/web/main.gogo
func main() {
    mux := http.NewServeMux()

    // Create a file server which serves files out of the "./ui/static" directory.
    // Note that the path given to the http.Dir function is relative to the project
    // directory root.
    fileServer := http.FileServer(http.Dir("./ui/static/"))

    // Use the mux.Handle() function to register the file server as the handler for
    // all URL paths that start with "/static/". For matching paths, we strip the
    // "/static" prefix before the request reaches the file server.
    mux.Handle("/static/", http.StripPrefix("/static", fileServer))

    // Register the other application routes as normal.
    mux.HandleFunc("/", home)
    mux.HandleFunc("/snippet/view", snippetView)
    mux.HandleFunc("/snippet/create", snippetCreate)

    log.Print("Starting server on :4000")
    err := http.ListenAndServe(":4000", mux)
    log.Fatal(err)
}

Finally the base template links the stylesheet, the favicon, the Ubuntu Mono webfont and the JavaScript file — and the page comes alive:

Additional information. The file server cleans every path with path.Clean() (blocking directory traversal), supports Range requests — curl -H "Range: bytes=100-199" returns 206 Partial Content — handles Last-Modified/If-Modified-Since with 304 Not Modified, and sets Content-Type from the extension via mime.TypeByExtension(). Frequently served files are usually read from the OS cache rather than disk. For one-off files use http.ServeFile() — but it does not sanitise paths, so clean untrusted input with filepath.Clean(). To disable directory listings, drop a blank index.html in each directory, or implement a custom http.FileSystem that returns os.ErrNotExist for directories.

2.9 · The http.Handler interface

Strictly, a handler is any object satisfying this interface:

net/httpgo
type Handler interface {
    ServeHTTP(ResponseWriter, *Request)
}

So the minimum handler is any type with a ServeHTTP(http.ResponseWriter, *http.Request) method — a struct, a string, anything:

A handler typego
type home struct{}

func (h *home) ServeHTTP(w http.ResponseWriter, r *http.Request) {
    w.Write([]byte("This is my home page"))
}

mux := http.NewServeMux()
mux.Handle("/", &home{})

Creating an object just to hang a method on is long-winded, which is why handlers are written as plain functions. Such a function is not itself a handler — the http.HandlerFunc() adapter adds the ServeHTTP() method for you:

Function → handlergo
mux.Handle("/", http.HandlerFunc(home))   // what HandleFunc() does for us
mux.HandleFunc("/", home)              // ...so we normally write this

Chaining handlers

http.ListenAndServe(addr string, handler Handler) wants a Handler — and a servemux qualifies, because it has a ServeHTTP() method too. The servemux is best understood as a special handler that passes the request to a second handler instead of answering itself. A Go web app is a chain of ServeHTTP() calls; middleware later in the book extends the chain.

Requests are handled concurrently. Every incoming request is served in its own goroutine. That is a large part of why Go servers are fast — and why shared state accessed from handlers needs protecting against race conditions.
