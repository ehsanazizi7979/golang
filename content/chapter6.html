Chapter 6 — Middleware

“Code that runs for every request”

Some behaviour belongs to no single handler: logging every request, adding security headers, recovering from panics, checking a cache. Chapter 6 expresses all of it as middleware — small handlers that act on a request before or after the real one — and then shows how to compose them without the nesting getting out of hand.

A note on the live demo. The five headers below are set on real responses by a chain that really executes, and /middleware traces every link on the way down and back up. The template pages from chapter 5 now serve through that chain, so they carry the headers too.

6.1 · How middleware works

The book's framing: “You can think of a Go web application as a chain of ServeHTTP() methods being called one after another.” Right now the server calls the servemux's ServeHTTP(), which looks up a handler and calls that handler's ServeHTTP(). Middleware inserts another handler into that chain.

You have already been using some: http.StripPrefix() from chapter 2.8 is middleware that rewrites the path before passing the request to the file server.

The standard patterngo
func myMiddleware(next http.Handler) http.Handler {
    fn := func(w http.ResponseWriter, r *http.Request) {
        // TODO: Execute our middleware logic here...
        next.ServeHTTP(w, r)
    }
    return http.HandlerFunc(fn)
}

That is a wrapper around the next handler. fn is a closure over next, so it always has access to it, and http.HandlerFunc() adapts the function to the http.Handler interface. The idiom you will see most in the wild is the anonymous version:

Simplifying the middlewarego
func myMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        // TODO: Execute our middleware logic here...
        next.ServeHTTP(w, r)
    })
}

Position determines reach

Before the servemux, middleware acts on every request — right for logging:

myMiddleware → servemux → application handler

After the servemux, by wrapping one route, it acts only on that route — right for authorization:

servemux → myMiddleware → application handler

6.2 · Setting security headers

Five headers, in line with current OWASP guidance, on every response:

HeaderWhat it does
Content-Security-Policy Restricts where resources may be loaded from — the main defence against XSS, clickjacking and code injection. Here: fonts from fonts.gstatic.com, styles from fonts.googleapis.com and self, everything else self. Inline JavaScript is blocked.
Referrer-Policy origin-when-cross-origin: the full URL for same-origin requests, but path and query string stripped when navigating away.
X-Content-Type-Options nosniff — stop browsers MIME-sniffing the content type, which prevents content-sniffing attacks.
X-Frame-Options deny — clickjacking protection for older browsers that don't support CSP.
X-XSS-Protection 0 — disable the browser's XSS filter. It used to be 1; mode=block, but alongside CSP the recommendation is now to turn it off.
File: cmd/web/middleware.gogo
package main

import (
    "net/http"
)

func secureHeaders(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        // Note: This is split across multiple lines for readability. You don't 
        // need to do this in your own code.
        w.Header().Set("Content-Security-Policy",
            "default-src 'self'; style-src 'self' fonts.googleapis.com; font-src fonts.gstatic.com")
        w.Header().Set("Referrer-Policy", "origin-when-cross-origin")
        w.Header().Set("X-Content-Type-Options", "nosniff")
        w.Header().Set("X-Frame-Options", "deny")
        w.Header().Set("X-XSS-Protection", "0")

        next.ServeHTTP(w, r)
    })
}

To cover every request it must wrap the servemux — which means routes() has to return an http.Handler rather than *http.ServeMux:

File: cmd/web/routes.gogo
// Update the signature for the routes() method so that it returns a
// http.Handler instead of *http.ServeMux.
func (app *application) routes() http.Handler {
    mux := http.NewServeMux()

    fileServer := http.FileServer(http.Dir("./ui/static/"))
    mux.Handle("/static/", http.StripPrefix("/static", fileServer))

    mux.HandleFunc("/", app.home)
    mux.HandleFunc("/snippet/view", app.snippetView)
    mux.HandleFunc("/snippet/create", app.snippetCreate)

    // Pass the servemux as the 'next' parameter to the secureHeaders middleware.
    // Because secureHeaders is just a function, and the function returns a
    // http.Handler we don't need to do anything else.
    return secureHeaders(mux)
}

Flow of control runs in both directions. When the last handler returns, control passes back up the chain in reverse:

secureHeaders → servemux → application handler → servemux → secureHeaders

Code before next.ServeHTTP() runs on the way down; code after it — or in a deferred function — runs on the way back up. Live: /middleware shows exactly this, link by link.

Early returns stop the chain. Return before calling next.ServeHTTP() and nothing further runs — the basis of authentication middleware:

if !isAuthorized(r) {
    w.WriteHeader(http.StatusForbidden)
    return   // chain stops here
}
next.ServeHTTP(w, r)

6.3 · Request logging

This middleware needs the application's logger, so it is a method on *application — the same dependency-injection pattern from chapter 3, and the same function signature as any other middleware.

File: cmd/web/middleware.go — logRequest()go
func (app *application) logRequest(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        app.infoLog.Printf("%s - %s %s %s", r.RemoteAddr, r.Proto, r.Method, r.URL.RequestURI())
        next.ServeHTTP(w, r)
    })
}

Added to the chain so it runs first, for every request — reading left to right:

logRequest ↔ secureHeaders ↔ servemux ↔ application handler
File: cmd/web/routes.gogo
// Wrap the existing chain with the logRequest middleware.
return app.logRequest(secureHeaders(mux))

6.4 · Panic recovery

A panic in a plain Go program terminates it. Go's HTTP server is more careful: the panic is isolated to the goroutine serving that request. The server logs a stack trace, unwinds that goroutine (running deferred functions), and closes the HTTP connection — the server survives.

But look at what the user gets. Add panic("oops! something went wrong") to the home handler and:

Terminal — an empty replyshell
$ curl -i http://localhost:4000
curl: (52) Empty reply from server

No status, no body, no explanation. The fix uses the fact that deferred functions always run while the stack unwinds:

File: cmd/web/middleware.go — recoverPanic()go
func (app *application) recoverPanic(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        // Create a deferred function (which will always be run in the event
        // of a panic as Go unwinds the stack).
        defer func() {
            // Use the builtin recover function to check if there has been a
            // panic or not. If there has...
            if err := recover(); err != nil {
                // Set a "Connection: close" header on the response.
                w.Header().Set("Connection", "close")
                // Call the app.serverError helper method to return a 500
                // Internal Server response.
                app.serverError(w, fmt.Errorf("%s", err))
            }
        }()

        next.ServeHTTP(w, r)
    })
}

Two details worth knowing. Connection: close makes Go's server close the connection after the response and tells the client that is going to happen (over HTTP/2 Go strips it and sends a GOAWAY frame instead, so the response stays well-formed). And the value returned by recover() has type any — it is whatever was passed to panic(), a string, an error, or anything else — so the book normalises it with fmt.Errorf("%s", err) before handing it to serverError().

It goes first in the chain, so it covers panics in all the middleware and handlers after it:

File: cmd/web/routes.gogo
// Wrap the existing chain with the recoverPanic middleware.
return app.recoverPanic(app.logRequest(secureHeaders(mux)))

Live: /middleware/panic runs both versions. Without the middleware: an empty reply and no trace at all. With it: 500, Connection: close, all five security headers, and the chain's events including recoverPanic(recovered).

Panics in other goroutines are not recovered. The middleware only recovers in its own goroutine. Spin up a background goroutine and a panic there is caught neither by recoverPanic() nor by the server — the whole process exits. Recover inside it yourself:

go func() {
    defer func() {
        if err := recover(); err != nil {
            log.Print(fmt.Errorf("%s\n%s", err, debug.Stack()))
        }
    }()
    doSomeBackgroundProcessing()
}()

6.5 · Composable middleware chains

justinas/alice turns nested wrapping into a list. This:

return myMiddleware1(myMiddleware2(myMiddleware3(myHandler)))

becomes this:

return alice.New(myMiddleware1, myMiddleware2, myMiddleware3).Then(myHandler)

And because a chain is a value, it can be named, extended and reused — which is the real payoff as routes multiply:

myChain := alice.New(myMiddlewareOne, myMiddlewareTwo)
myOtherChain := myChain.Append(myMiddleware3)
return myOtherChain.Then(myHandler)

File: cmd/web/routes.go — the finished chaingo
package main

import (
    "net/http"

    "github.com/justinas/alice" // New import
)

func (app *application) routes() http.Handler {
    mux := http.NewServeMux()

    fileServer := http.FileServer(http.Dir("./ui/static/"))
    mux.Handle("/static/", http.StripPrefix("/static", fileServer))

    mux.HandleFunc("/", app.home)
    mux.HandleFunc("/snippet/view", app.snippetView)
    mux.HandleFunc("/snippet/create", app.snippetCreate)

    // Create a middleware chain containing our 'standard' middleware
    // which will be used for every request our application receives.
    standard := alice.New(app.recoverPanic, app.logRequest, secureHeaders)

    // Return the 'standard' middleware chain followed by the servemux.
    return standard.Then(mux)
}

Order matters, and it is not symmetric. alice.New(a, b, c).Then(h) equals a(b(c(h))): a is outermost, so it sees the request first and the response last. That is why recoverPanic leads — it has to wrap the others to recover their panics. Live: /middleware/alice shows the equivalence, and /middleware runs this exact chain.
