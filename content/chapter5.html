Chapter 5 — Dynamic HTML templates

“From struct dumps to real pages”

Chapter 4 could show you a snippet. Chapter 5 makes it look like something a person would use: one holding structure for dynamic data, the actions and functions that control what gets rendered, a template cache so pages aren't re-parsed on every request, a render helper that fails safely, common data on every page, and custom functions for formatting.

A note on the live demo. The pages at /newsnippets and /newsnippets/view?id=1 are rendered by the same base.tmpl, nav.tmpl, home.tmpl and view.tmpl files the book writes, through a working implementation of html/template (dot, with/if/range, pipelines, template variables, FuncMap, and context-aware escaping). Nothing about the markup below is a mock-up.

5.1 · Displaying dynamic data

In chapter 4, snippetView ended with fmt.Fprintf(w, "%+v", snippet) — a debugging dump. The first step is to hand that data to a template instead. A template set is base layout + partials + page, parsed together with template.ParseFiles() and executed by name.

File: cmd/web/handlers.go — snippetView()go
// Initialize a slice containing the paths to the view.tmpl file,
// plus the base layout and navigation partial that we made earlier.
files := []string{
    "./ui/html/base.tmpl",
    "./ui/html/partials/nav.tmpl",
    "./ui/html/pages/view.tmpl",
}

// Parse the template files...
ts, err := template.ParseFiles(files...)
if err != nil {
    app.serverError(w, err)
    return
}

// And then execute them. Notice how we are passing in the snippet
// data (a models.Snippet struct) as the final parameter?
err = ts.ExecuteTemplate(w, "base", snippet)
if err != nil {
    app.serverError(w, err)
}

Any dynamic data you pass in is represented inside the template by dot (a single .). When dot's underlying type is a struct, you yield any exported field by postfixing dot with the field name — {{.Title}}.

File: ui/html/pages/view.tmpltmpl
{{define "title"}}Snippet #{{.ID}}{{end}}

{{define "main"}}
    <div class='snippet'>
        <div class='metadata'>
            <strong>{{.Title}}</strong>
            <span>#{{.ID}}</span>
        </div>
        <pre><code>{{.Content}}</code></pre>
        <div class='metadata'>
            <time>Created: {{.Created}}</time>
            <time>Expires: {{.Expires}}</time>
        </div>
    </div>
{{end}}

Rendering multiple pieces of data

html/template lets you pass one — and only one — item of dynamic data. Real pages need several. The lightweight, type-safe answer is a struct that acts as a single holding structure: a templateData type.

File: cmd/web/templates.gogo
package main

import "snippetbox.alexedwards.net/internal/models"

// Define a templateData type to act as the holding structure for
// any dynamic data that we want to pass to our HTML templates.
// At the moment it only contains one field, but we'll add more
// to it as the build progresses.
type templateData struct {
    Snippet *models.Snippet
}

Now the template must chain the field names: {{.Snippet.Title}} rather than {{.Title}}. Section 5.2's {{with}} action removes that repetition again.

Additional information: dynamic content escaping. html/template automatically escapes anything yielded between {{ }} tags — which is exactly why you use it instead of text/template. A value of:

<span>{{"<script>alert('xss attack')</script>"}}</span>

is rendered harmlessly as:

<span>&lt;script&gt;alert(&#39;xss attack&#39;)&lt;/script&gt;</span>

The escaping is context-dependent: Go uses different escapes depending on whether the value lands in HTML text, an attribute, CSS, JavaScript or a URI. Live: /tplx/escape renders the same payload through both packages so you can see the difference.

Nested templates. When invoking one template from another, dot must be passed explicitly — {{template "main" .}}, not {{template "main"}}. Get in the habit of always pipelining it. Calling methods. Fields with methods can call them, one return value only: {{.Snippet.Created.Weekday}}, and with arguments, space-separated and unparenthesised: {{.Snippet.Created.AddDate 0 6 0}}. Comments. html/template strips all HTML comments, including conditional comments, because it cannot reliably predict how a browser would interpret them.

5.2 · Template actions and functions

Three actions control the display of data, and all three change what dot means inside their block:

ActionWhat it does
{{if .Foo}} C1 {{else}} C2 {{end}} Render C1 if .Foo is not empty, otherwise C2.
{{with .Foo}} C1 {{else}} C2 {{end}} If .Foo is not empty, set dot to .Foo and render C1, otherwise C2.
{{range .Foo}} C1 {{else}} C2 {{end}} If .Foo has length, loop over it setting dot to each element and render C1; if empty, render C2.

{{else}} is optional in all three. The empty values are false, 0, any nil pointer or interface, and any array, slice, map or string of length zero. And the crucial point: with and range change dot, so what dot refers to depends on where you are in the template.

The most useful functions: eq, ne, not, or, index, printf, len, and template variables like {{$bar := len .Foo}} (a dollar prefix, alphanumeric only).

File: ui/html/pages/view.tmpl — withtmpl
{{define "title"}}Snippet #{{.Snippet.ID}}{{end}}

{{define "main"}}
    {{with .Snippet}}
    <div class='snippet'>
        <div class='metadata'>
            <strong>{{.Title}}</strong>
            <span>#{{.ID}}</span>
        </div>
        <pre><code>{{.Content}}</code></pre>
        <div class='metadata'>
            <time>Created: {{.Created}}</time>
            <time>Expires: {{.Expires}}</time>
        </div>
    </div>
    {{end}}
{{end}}

Between {{with .Snippet}} and its {{end}}, dot is the snippet, so the inner fields need no prefix. Then the home page gets a table, with {{if}} for the empty case and {{range}} for the rows:

File: ui/html/pages/home.tmpltmpl
{{define "title"}}Home{{end}}

{{define "main"}}
    <h2>Latest Snippets</h2>

    {{if .Snippets}}
    <table>
        <tr>
            <th>Title</th>
            <th>Created</th>
            <th>ID</th>
        </tr>
        {{range .Snippets}}
        <tr>
            <td><a href='/snippet/view?id={{.ID}}'>{{.Title}}</a></td>
            <td>{{.Created}}</td>
            <td>#{{.ID}}</td>
        </tr>
        {{end}}
    </table>
    {{else}}
        <p>There's nothing to see here... yet!</p>
    {{end}}
{{end}}

Combining functions. Parentheses group functions and their arguments:

{{if (gt (len .Foo) 99)}} C1 {{end}}
{{if (and (eq .Foo 1) (le .Bar 20))}} C1 {{end}}

Controlling loops. {{break}} ends a range early and {{continue}} skips to the next iteration — both live in the playground at /tplx.

5.3 · Caching templates

Two problems at this point. Every request re-reads and re-parses its templates from disk; and the home and view handlers now duplicate the same parse-execute-error dance. The first is solved with an in-memory cache of parsed template sets:

File: cmd/web/templates.go — newTemplateCache()go
func newTemplateCache() (map[string]*template.Template, error) {
    // Initialize a new map to act as the cache.
    cache := map[string]*template.Template{}

    // Use the filepath.Glob() function to get a slice of all filepaths that
    // match the pattern "./ui/html/pages/*.tmpl". This will essentially gives
    // us a slice of all the filepaths for our application 'page' templates
    // like: [ui/html/pages/home.tmpl ui/html/pages/view.tmpl]
    pages, err := filepath.Glob("./ui/html/pages/*.tmpl")
    if err != nil {
        return nil, err
    }

    // Loop through the page filepaths one-by-one.
    for _, page := range pages {
        // Extract the file name (like 'home.tmpl') from the full filepath
        // and assign it to the name variable.
        name := filepath.Base(page)

        // Create a slice containing the filepaths for our base template, any
        // partials and the page.
        files := []string{
            "./ui/html/base.tmpl",
            "./ui/html/partials/nav.tmpl",
            page,
        }

        // Parse the files into a template set.
        ts, err := template.ParseFiles(files...)
        if err != nil {
            return nil, err
        }

        // Add the template set to the map, using the name of the page
        // (like 'home.tmpl') as the key.
        cache[name] = ts
    }

    // Return the map.
    return cache, nil
}

It's built in main() and injected through the application struct like every other dependency — and because a template set that fails to parse is a programming error, main() treats it as fatal:

File: cmd/web/main.gogo
// Add a templateCache field to the application struct.
type application struct {
    errorLog      *log.Logger
    infoLog       *log.Logger
    snippets      *models.SnippetModel
    templateCache map[string]*template.Template
}

// Initialize a new template cache...
templateCache, err := newTemplateCache()
if err != nil {
    errorLog.Fatal(err)
}

// And add it to the application dependencies.
app := &application{
    errorLog:      errorLog,
    infoLog:       infoLog,
    snippets:      &models.SnippetModel{DB: db},
    templateCache: templateCache,
}

The second problem — duplication — is solved by a render() helper method:

File: cmd/web/helpers.go — render()go
func (app *application) render(w http.ResponseWriter, status int, page string, data *templateData) {
    // Retrieve the appropriate template set from the cache based on the page
    // name (like 'home.tmpl'). If no entry exists in the cache with the
    // provided name, then create a new error and call the serverError() helper
    // method that we made earlier and return.
    ts, ok := app.templateCache[page]
    if !ok {
        err := fmt.Errorf("the template %s does not exist", page)
        app.serverError(w, err)
        return
    }

    // Write out the provided HTTP status code ('200 OK', '400 Bad Request'
    // etc).
    w.WriteHeader(status)

    // Execute the template set and write the response body. Again, if there
    // is any error we call the the serverError() helper.
    err := ts.ExecuteTemplate(w, "base", data)
    if err != nil {
        app.serverError(w, err)
    }
}

Which collapses both handlers to their actual job — fetch data, then render:

File: cmd/web/handlers.gogo
// Use the new render helper.
app.render(w, http.StatusOK, "home.tmpl", &templateData{
    Snippets: snippets,
})

// ...and in snippetView():
app.render(w, http.StatusOK, "view.tmpl", &templateData{
    Snippet: snippet,
})

Finally, newTemplateCache() is made flexible so any new partial is picked up automatically, rather than naming nav.tmpl by hand:

File: cmd/web/templates.go — automatically parsing partialsgo
for _, page := range pages {
    name := filepath.Base(page)

    // Parse the base template file into a template set.
    ts, err := template.ParseFiles("./ui/html/base.tmpl")
    if err != nil {
        return nil, err
    }

    // Call ParseGlob() *on this template set* to add any partials.
    ts, err = ts.ParseGlob("./ui/html/partials/*.tmpl")
    if err != nil {
        return nil, err
    }

    // Call ParseFiles() *on this template set* to add the  page template.
    ts, err = ts.ParseFiles(page)
    if err != nil {
        return nil, err
    }

    // Add the template set to the map as normal...
    cache[name] = ts
}

5.4 · Catching runtime errors

Dynamic behaviour brings runtime errors. The book adds {{len nil}} to view.tmpl — which compiles fine, because nil has no length only when the command actually executes.

File: ui/html/pages/view.tmpl — with a deliberate errortmpl
{{define "main"}}
    {{with .Snippet}}
    <div class='snippet'>
        <div class='metadata'>
            <strong>{{.Title}}</strong>
            <span>#{{.ID}}</span>
        </div>
        {{len nil}} <!-- Deliberate error -->
        <pre><code>{{.Content}}</code></pre>
    </div>
    {{end}}
{{end}}

What comes back is the interesting part: 200 OK, a Content-Length header — and a page that stops mid-sentence, with the words Internal Server Error where the content should be. The status line has already gone out; there is no taking it back.

Terminal — the half-written 200shell
$ curl -i "http://localhost:4000/snippet/view?id=1"
HTTP/1.1 200 OK
Content-Length: 762
Content-Type: text/html; charset=utf-8

<!doctype html>
...
    <div class='snippet'>
        <div class='metadata'>
            <strong>An old silent pond</strong>
            <span>#1</span>
        </div>
        Internal Server Error

The fix is a two-stage render: execute into a buffer first, and only write the status and the body if that succeeds.

File: cmd/web/helpers.go — the buffered render()go
// Initialize a new buffer.
buf := new(bytes.Buffer)

// Write the template to the buffer, instead of straight to the
// http.ResponseWriter. If there's an error, call our serverError() helper
// and then return.
err := ts.ExecuteTemplate(buf, "base", data)
if err != nil {
    app.serverError(w, err)
    return
}

// If the template is written to the buffer without any errors, we are safe
// to go ahead and write the HTTP status code to http.ResponseWriter.
w.WriteHeader(status)

// Write the contents of the buffer to the http.ResponseWriter. Note: this
// is another time where we pass our http.ResponseWriter to a function that
// takes an io.Writer.
buf.WriteTo(w)

Now the same request produces a clean 500 Internal Server Error, a plain-text body, and no half-page leakage. Live: /tplx/error runs both versions side by side and shows the exact template error, with its line and column.

5.5 · Common dynamic data

Some data belongs on every page — a user's name, a CSRF token, or here, the current year in the footer. Add the field to templateData, then add a helper that produces it:

File: cmd/web/templates.go, then helpers.gogo
// Add a CurrentYear field to the templateData struct.
type templateData struct {
    CurrentYear int
    Snippet     *models.Snippet
    Snippets    []*models.Snippet
}

// Create an newTemplateData() helper, which returns a pointer to a templateData
// struct initialized with the current year. Note that we're not using the 
// *http.Request parameter here at the moment, but we will do later in the book.
func (app *application) newTemplateData(r *http.Request) *templateData {
    return &templateData{
        CurrentYear: time.Now().Year(),
    }
}

The handlers then take the default data and add their own, which is the pattern every later chapter builds on:

File: cmd/web/handlers.gogo
// Call the newTemplateData() helper to get a templateData struct containing
// the 'default' data (which for now is just the current year), and add the
// snippets slice to it.
data := app.newTemplateData(r)
data.Snippets = snippets

// Pass the data to the render() helper as normal.
app.render(w, http.StatusOK, "home.tmpl", data)
File: ui/html/base.tmpl — the footertmpl
<footer>
    <!-- Update the footer to include the current year -->
    Powered by <a href='https://golang.org/'>Go</a> in {{.CurrentYear}}
</footer>

5.6 · Custom template functions

The dates still read 2022-04-05 07:20:05 +0000 UTC. A custom function fixes that. Two steps: a template.FuncMap mapping names to functions, and template.Funcs() registering it before any parsing.

File: cmd/web/templates.go — humanDate()go
// Create a humanDate function which returns a nicely formatted string
// representation of a time.Time object.
func humanDate(t time.Time) string {
    return t.Format("02 Jan 2006 at 15:04")
}

// Initialize a template.FuncMap object and store it in a global variable. This is
// essentially a string-keyed map which acts as a lookup between the names of our
// custom template functions and the functions themselves.
var functions = template.FuncMap{
    "humanDate": humanDate,
}
File: cmd/web/templates.go — registering the FuncMapgo
// The template.FuncMap must be registered with the template set before you
// call the ParseFiles() method. This means we have to use template.New() to
// create an empty template set, use the Funcs() method to register the
// template.FuncMap, and then parse the file as normal.
ts, err := template.New(name).Funcs(functions).ParseFiles("./ui/html/base.tmpl")
if err != nil {
    return nil, err
}

ts, err = ts.ParseGlob("./ui/html/partials/*.tmpl")
if err != nil {
    return nil, err
}

ts, err = ts.ParseFiles(page)
if err != nil {
    return nil, err
}

A custom function can take as many parameters as it likes but must return one value — or a value and an error. Used in the templates, it behaves like any built-in:

File: ui/html/pages/home.tmpl and view.tmpltmpl
<td><a href='/snippet/view?id={{.ID}}'>{{.Title}}</a></td>
<!-- Use the new template function here -->
<td>{{humanDate .Created}}</td>
<td>#{{.ID}}</td>

...and in view.tmpl:
<time>Created: {{humanDate .Created}}</time>
<time>Expires: {{humanDate .Expires}}</time>
