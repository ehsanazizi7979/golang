Chapter 7 — Advanced routing

“Method-based routing and clean URLs”

Chapter 8 needs one route to do two different jobs depending on the method, and it needs URLs like /snippet/view/123 instead of ?id=123. Go's ServeMux can do neither. So chapter 7 replaces it with a third-party router — and shows what that buys, and what it costs.

A note on the live demo. /clean is the same application running on a working implementation of julienschmidt/httprouter: named parameters, catch-alls, automatic OPTIONS, Allow headers on 405s, custom 404 and 405 handlers, and conflicting patterns rejected at registration. The rest of this server still runs on the chapter-2 ServeMux, so the two can be compared.

7.1 · Choosing a router

There are hundreds of third-party routers, and they all work slightly differently — different APIs, different matching logic, different quirks. The book recommends three as a starting point: julienschmidt/httprouter, go-chi/chi and gorilla/mux. All three support method-based routing and clean URLs, and all three work with the handler and middleware patterns the book has been using.

RouterStrengthsWeaknesses
julienschmidt/httprouter The most focused, lightweight and fastest of the three; closest to “perfect” on HTTP spec compliance. Handles OPTIONS automatically, sends 405s correctly, and lets you set custom 404 and 405 handlers. No regexp patterns, no route grouping.
go-chi/chi Similar feature set, plus regexp route patterns and grouping of routes that share middleware — valuable in larger applications. Doesn't handle OPTIONS automatically, and doesn't set an Allow header on 405s.
gorilla/mux The most full-featured: regexp patterns, routing by scheme, host and headers, and the only one with custom routing rules and route reversing (as in Django, Rails or Laravel). No longer actively maintained (archived). Comparatively slow and memory-hungry, and like chi it doesn't handle OPTIONS or set Allow.

For a small application needing only method-based routing and clean URLs, the book picks httprouter “for the sake of performance and correctness”.

On gorilla/mux being archived. That doesn't automatically make it a bad choice: the code is stable and battle-hardened, and the Go compatibility promise means it will keep compiling. What you lose is bug fixes.

7.2 · Clean URLs and method-based routing

The syntax in one line:

The core patterngo
router := httprouter.New()
router.HandlerFunc(http.MethodGet, "/snippet/view/:id", app.snippetView)
  • The first argument is the method the request must have — http.MethodGet, not the string "GET".
  • The second is a pattern. :name is a named parameter matching one path segment, so /snippet/view/123 and /snippet/view/foo both match /snippet/view/:id, but /snippet/bar and /snippet/view/foo/baz do not.
  • *name is a catch-all matching everything, only allowed at the end of a pattern — /static/*filepath.
  • The pattern / matches only a path of exactly /.
  • Handler() takes an http.Handler rather than a function — which is how the static file server is registered.
File: cmd/web/routes.gogo
func (app *application) routes() http.Handler {
    // Initialize the router.
    router := httprouter.New()

    // Update the pattern for the route for the static files.
    fileServer := http.FileServer(http.Dir("./ui/static/"))
    router.Handler(http.MethodGet, "/static/*filepath", http.StripPrefix("/static", fileServer))

    // And then create the routes using the appropriate methods, patterns and 
    // handlers.
    router.HandlerFunc(http.MethodGet, "/", app.home)
    router.HandlerFunc(http.MethodGet, "/snippet/view/:id", app.snippetView)
    router.HandlerFunc(http.MethodGet, "/snippet/create", app.snippetCreate)
    router.HandlerFunc(http.MethodPost, "/snippet/create", app.snippetCreatePost)

    // Create the middleware chain as normal.
    standard := alice.New(app.recoverPanic, app.logRequest, secureHeaders)

    // Wrap the router with the middleware and return it as normal.
    return standard.Then(router)
}

The handlers change in three ways. The id is read from the request context rather than the query string; the manual method check in the create handler disappears, because httprouter does it; and the redirect uses the new URL shape.

File: cmd/web/handlers.go — snippetView()go
// Because httprouter matches the "/" path exactly, we can now remove the
// manual check of r.URL.Path != "/" from this handler.

// When httprouter is parsing a request, the values of any named parameters
// will be stored in the request context. We'll talk about request context
// in detail later in the book, but for now it's enough to know that you can
// use the ParamsFromContext() function to retrieve a slice containing these
// parameter names and values like so:
params := httprouter.ParamsFromContext(r.Context())

// We can then use the ByName() method to get the value of the "id" named
// parameter from the slice and validate it as normal.
id, err := strconv.Atoi(params.ByName("id"))
File: cmd/web/handlers.go — the two create handlersgo
// Add a new snippetCreate handler, which for now returns a placeholder
// response. We'll update this shortly to show a HTML form.
func (app *application) snippetCreate(w http.ResponseWriter, r *http.Request) {
    w.Write([]byte("Display the form for creating a new snippet..."))
}

// Rename this handler to snippetCreatePost.
func (app *application) snippetCreatePost(w http.ResponseWriter, r *http.Request) {
    // Checking if the request method is a POST is now superfluous and can be
    // removed, because this is done automatically by httprouter.
    title := "O snail"
    content := "O snail\nClimb Mount Fuji,\nBut slowly, slowly!\n\n– Kobayashi Issa"
    expires := 7

    id, err := app.snippets.Insert(title, content, expires)
    if err != nil {
        app.serverError(w, err)
        return
    }

    // Update the redirect path to use the new clean URL format.
    http.Redirect(w, r, fmt.Sprintf("/snippet/view/%d", id), http.StatusSeeOther)
}

Method Not Allowed

Custom error handlers

Two 404s, two different bodies. /snippet/view/99 has no such record, so it calls app.notFound(); /missing has no such route, so httprouter answers it itself:

Terminal — the discrepancyshell
$ curl http://localhost:4000/snippet/view/99
Not Found
$ curl http://localhost:4000/missing
404 page not found

httprouter makes the fix a one-liner — and the same field exists for 405s:

File: cmd/web/routes.gogo
router := httprouter.New()

// Create a handler function which wraps our notFound() helper, and then
// assign it as the custom handler for 404 Not Found responses. You can also
// set a custom handler for 405 Method Not Allowed responses by setting
// router.MethodNotAllowed in the same way too.
router.NotFound = http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    app.notFound(w)
})
Terminal — consistent againshell
$ curl http://localhost:4000/snippet/view/99
Not Found
$ curl http://localhost:4000/missing
Not Found

Conflicting route patterns are rejected. httprouter refuses two patterns that could match the same request — GET /foo/new alongside GET /foo/:name or GET /foo/*name. That is usually a good thing: with no conflicts there are no routing-priority rules to reason about. If you genuinely need conflicting routes (replicating an existing application's endpoints, say), use chi or gorilla/mux.

Customising behaviour. httprouter also offers trailing-slash redirects and automatic path cleaning.

Why not RESTful URLs? GET /snippets/:id and GET /snippets/new conflict — a request to /snippets/new matches both, with id set to "new". And the form at /snippets/new would have to post to /snippets, so re-rendering it after a validation error would change the URL in the user's address bar. Not fatal — but clunky.

Handler naming. There is no right or wrong convention in Go. This project postfixes POST handlers with Post: snippetCreate and snippetCreatePost.
