Chapter 8 — Processing forms

“Post-Redirect-Get, and a form that argues back”

Chapter 7 gave the application a GET and a POST on the same pattern. This chapter fills them in: a real HTML form, untrusted input parsed out of the request body, validation rules that produce per-field error messages, and a redirect at the end so a refresh can't submit twice.

Everything here follows one workflow — Post-Redirect-Get:

  1. The user makes a GET /snippet/create and is shown the blank form.
  2. The user fills it in; the browser sends the data as POST /snippet/create.
  3. snippetCreatePost validates. On failure the form is re-displayed with the offending fields highlighted and the submitted values still in place. On success the snippet is inserted and the user is redirected to /snippet/view/:id.

By the end of the chapter the handler has been rewritten four times — ParseForm and strconv.Atoi, then hand-rolled validation, then an internal/validator package, then automatic decoding with go-playground/form. Each rewrite removes code without changing what the user sees. The demo runs the final version, and lets you step back through the earlier ones.

8.2 · Parsing form data

Chapter 7's POST /snippet/create already lands in snippetCreatePost. Processing the body is two steps: parse it into the request, then read the values out.

r.ParseForm() checks the body is well-formed and stores the data in r.PostForm. It returns an error for a missing or oversized body — which is a client error, so 400. It is also idempotent: calling it twice on the same request is harmless, which matters once helpers start calling it too.

File: cmd/web/handlers.go — first versiongo
func (app *application) snippetCreatePost(w http.ResponseWriter, r *http.Request) {
    // First we call r.ParseForm() which adds any data in POST request bodies
    // to the r.PostForm map. This also works in the same way for PUT and PATCH
    // requests. If there are any errors, we use our app.ClientError() helper to
    // send a 400 Bad Request response to the user.
    err := r.ParseForm()
    if err != nil {
        app.clientError(w, http.StatusBadRequest)
        return
    }

    // Use the r.PostForm.Get() method to retrieve the title and content
    // from the r.PostForm map.
    title := r.PostForm.Get("title")
    content := r.PostForm.Get("content")

    // The r.PostForm.Get() method always returns the form data as a *string*.
    // However, we're expecting our expires value to be a number, and want to
    // represent it in our Go code as an integer. So we need to manually covert
    // the form data to an integer using strconv.Atoi(), and we send a 400 Bad
    // Request response if the conversion fails.
    expires, err := strconv.Atoi(r.PostForm.Get("expires"))
    if err != nil {
        app.clientError(w, http.StatusBadRequest)
        return
    }

    id, err := app.snippets.Insert(title, content, expires)
    if err != nil {
        app.serverError(w, err)
        return
    }

    http.Redirect(w, r, fmt.Sprintf("/snippet/view/%d", id), http.StatusSeeOther)
}

Every form value arrives as a string, so anything numeric needs converting by hand — and Atoi failing is the client's fault, not the server's, hence another 400. A form field with no matching name in the request simply returns "", exactly like a missing query-string parameter.

The r.Form map

r.Form is the subtly different sibling. r.PostForm is populated only for POST, PATCH and PUT, and holds the request body only. r.Form is populated for every method, and holds the body and the query string — so a form posted to /snippet/create?foo=bar would also answer r.Form.Get("foo"). On a conflict the body value wins.

That is useful when an application accepts data from either place. Here it isn't: the data belongs in the body, so r.PostForm is the honest choice.

Why not FormValue?

r.FormValue() and r.PostFormValue() are shortcuts that call ParseForm() for you and then fetch the field. The book recommends avoiding them, for one reason: they silently discard the error from ParseForm(). Your application can be failing for real users with no way to report it.

Multiple-value fields

Get() returns only the first value, so it is useless for a group of checkboxes. The underlying type of r.PostForm is url.Values, whose underlying type is map[string][]string — so index the map directly:

Reading every value of a multi-value fieldgo
<input type="checkbox" name="items" value="foo"> Foo
<input type="checkbox" name="items" value="bar"> Bar
<input type="checkbox" name="items" value="baz"> Baz

for i, item := range r.PostForm["items"] {
    fmt.Fprintf(w, "%d: Item %s\n", i, item)
}

Limiting form size

Non-multipart POST, PUT and PATCH bodies are capped at 10MB by default; go past it and ParseForm() returns an error. To lower the limit:

Lowering the limit to 4KBgo
// Limit the request body size to 4096 bytes
r.Body = http.MaxBytesReader(w, r.Body, 4096)
err := r.ParseForm()
if err != nil {
    http.Error(w, "Bad Request", http.StatusBadRequest)
    return
}

Now only the first 4096 bytes are read, and a read beyond that makes MaxBytesReader return an error which ParseForm() surfaces. It also sets a flag on the http.ResponseWriter that tells the server to close the underlying TCP connection — so a client that keeps pushing bytes can't occupy a connection indefinitely.

8.3 · Validating form data

At this point the handler trusts the user completely. It shouldn't. For this form:

  • title and content must not be blank;
  • title must be no more than 100 characters;
  • expires must be exactly one of 1, 7 or 365.

All three are a few if statements plus strings and unicode/utf8:

File: cmd/web/handlers.go — validation bolted ongo
// Initialize a map to hold any validation errors for the form fields.
fieldErrors := make(map[string]string)

// Check that the title value is not blank and is not more than 100
// characters long. If it fails either of those checks, add a message to the
// errors map using the field name as the key.
if strings.TrimSpace(title) == "" {
    fieldErrors["title"] = "This field cannot be blank"
} else if utf8.RuneCountInString(title) > 100 {
    fieldErrors["title"] = "This field cannot be more than 100 characters long"
}

// Check that the Content value isn't blank.
if strings.TrimSpace(content) == "" {
    fieldErrors["content"] = "This field cannot be blank"
}

// Check the expires value matches one of the permitted values (1, 7 or
// 365).
if expires != 1 && expires != 7 && expires != 365 {
    fieldErrors["expires"] = "This field must equal 1, 7 or 365"
}

// If there are any errors, dump them in a plain text HTTP response and
// return from the handler.
if len(fieldErrors) > 0 {
    fmt.Fprint(w, fieldErrors)
    return
}
Runes, not bytes. The length check uses utf8.RuneCountInString(), not len(). len() counts bytes, and "Zoë" is 3 characters but 4 bytes because of the umlauted ë. A 100-byte limit would reject perfectly reasonable 60-character titles full of accented letters, emoji or CJK text.

Also note the else if: if the title is blank, the user gets the blank message, not both messages. That behaviour comes free from the structure here, and has to be reproduced deliberately by the helper version later.

8.4 · Displaying errors and repopulating fields

The next step is to hand those errors back to the template. First, a place to put them — the template data gains a Form field:

File: cmd/web/templates.gogo
// Add a Form field with the type "any".
type templateData struct {
    CurrentYear int
    Snippet     *models.Snippet
    Snippets    []*models.Snippet
    Form        any
}

any, because different forms will put different structs in it. Next, a struct that holds both the submitted values and the errors. Every field is exported — html/template can only read exported fields:

File: cmd/web/handlers.gogo
// Define a snippetCreateForm struct to represent the form data and validation
// errors for the form fields. Note that all the struct fields are deliberately
// exported (i.e. start with a capital letter). This is because struct fields
// must be exported in order to be read by the html/template package when
// rendering the template.
type snippetCreateForm struct {
    Title       string
    Content     string
    Expires     int
    FieldErrors map[string]string
}

The handler then builds one of those instead of loose variables, and re-renders the template on failure — with 422 Unprocessable Entity:

File: cmd/web/handlers.gogo
form := snippetCreateForm{
    Title:       r.PostForm.Get("title"),
    Content:     r.PostForm.Get("content"),
    Expires:     expires,
    FieldErrors: map[string]string{},
}

// ...the same four checks, operating on form.Title and friends...

// If there are any validation errors re-display the create.tmpl template,
// passing in the snippetCreateForm instance as dynamic data in the Form
// field. Note that we use the HTTP status code 422 Unprocessable Entity
// when sending the response to indicate that there was a validation error.
if len(form.FieldErrors) > 0 {
    data := app.newTemplateData(r)
    data.Form = form
    app.render(w, http.StatusUnprocessableEntity, "create.tmpl", data)
    return
}
Why 422 and not 400? The request was fine — it parsed, it decoded, the values were the right types. It is the content the server can't accept, and 422 says precisely that. A 400 is for a body that won't parse or a value that won't convert.

The template

Re-populating is just printing the struct's fields. The errors need one new idea: FieldErrors is a map[string]string keyed by form-field name, and template field chains work on map keys as well as struct fields — so {{.Form.FieldErrors.title}} looks up the key "title".

Map keys need no capitals. Unlike struct fields, which must be exported to be readable from a template, map keys are just strings and can be lowercase.
File: ui/html/pages/create.tmpltmpl
{{define "title"}}Create a New Snippet{{end}}

{{define "main"}}
<form action='/snippet/create' method='POST'>
    <div>
        <label>Title:</label>
        <!-- Use the `with` action to render the value of .Form.FieldErrors.title
        if it is not empty. -->
        {{with .Form.FieldErrors.title}}
            <label class='error'>{{.}}</label>
        {{end}}
        <!-- Re-populate the title data by setting the `value` attribute. -->
        <input type='text' name='title' value='{{.Form.Title}}'>
    </div>
    <div>
        <label>Content:</label>
        {{with .Form.FieldErrors.content}}
            <label class='error'>{{.}}</label>
        {{end}}
        <!-- Re-populate the content data as the inner HTML of the textarea. -->
        <textarea name='content'>{{.Form.Content}}</textarea>
    </div>
    <div>
        <label>Delete in:</label>
        {{with .Form.FieldErrors.expires}}
            <label class='error'>{{.}}</label>
        {{end}}
        <!-- Here we use the `if` action to check if the value of the re-populated
        expires field equals 365. If it does, then we render the `checked`
        attribute so that the radio input is re-selected. -->
        <input type='radio' name='expires' value='365' {{if (eq .Form.Expires 365)}}checked{{end}}> One Year
        <!-- And we do the same for the other possible values too... -->
        <input type='radio' name='expires' value='7' {{if (eq .Form.Expires 7)}}checked{{end}}> One Week
        <input type='radio' name='expires' value='1' {{if (eq .Form.Expires 1)}}checked{{end}}> One Day
    </div>
    <div>
        <input type='submit' value='Publish snippet'>
    </div>
</form>
{{end}}
The 500 you get for free. Run the application now and GET /snippet/create returns 500. snippetCreate never sets data.Form, so it is a nil any, and {{with .Form.FieldErrors.title}} tries to walk into nil. The fix is the same field that makes the feature possible — initialise a form in the GET handler, and use the opportunity to set a default:

File: cmd/web/handlers.gogo
func (app *application) snippetCreate(w http.ResponseWriter, r *http.Request) {
    data := app.newTemplateData(r)
    // Initialize a new createSnippetForm instance and pass it to the template.
    // Notice how this is also a great opportunity to set any default or
    // 'initial' values for the form --- here we set the initial value for the
    // snippet expiry to 365 days.
    data.Form = snippetCreateForm{
        Expires: 365,
    }
    app.render(w, http.StatusOK, "create.tmpl", data)
}

8.5 · Creating validation helpers

That works, but it is a lot of boilerplate for three fields, and a real application has many forms. The book extracts a small internal/validator package. It changes nothing for the user — this is a refactor.

File: internal/validator/validator.gogo
package validator

import (
    "strings"
    "unicode/utf8"
)

// Define a new Validator type which contains a map of validation errors for our
// form fields.
type Validator struct {
    FieldErrors map[string]string
}

// Valid() returns true if the FieldErrors map doesn't contain any entries.
func (v *Validator) Valid() bool {
    return len(v.FieldErrors) == 0
}

// AddFieldError() adds an error message to the FieldErrors map (so long as no
// entry already exists for the given key).
func (v *Validator) AddFieldError(key, message string) {
    // Note: We need to initialize the map first, if it isn't already
    // initialized.
    if v.FieldErrors == nil {
        v.FieldErrors = make(map[string]string)
    }

    if _, exists := v.FieldErrors[key]; !exists {
        v.FieldErrors[key] = message
    }
}

// CheckField() adds an error message to the FieldErrors map only if a
// validation check is not 'ok'.
func (v *Validator) CheckField(ok bool, key, message string) {
    if !ok {
        v.AddFieldError(key, message)
    }
}

// NotBlank() returns true if a value is not an empty string.
func NotBlank(value string) bool {
    return strings.TrimSpace(value) != ""
}

// MaxChars() returns true if a value contains no more than n characters.
func MaxChars(value string, n int) bool {
    return utf8.RuneCountInString(value) <= n
}

// PermittedInt() returns true if a value is in a list of permitted integers.
func PermittedInt(value int, permittedValues ...int) bool {
    for i := range permittedValues {
        if value == permittedValues[i] {
            return true
        }
    }
    return false
}

Two behaviours are worth naming. AddFieldError refuses to overwrite an existing message, so a field can carry at most one error and the first rule to fail is the one the user sees — which reproduces the else if from section 8.3 without the branching. And CheckField takes the check as a boolean rather than the value, so the rules read as sentences:

File: cmd/web/handlers.go — the form embeds the Validatorgo
// Remove the explicit FieldErrors struct field and instead embed the Validator
// type. Embedding this means that our snippetCreateForm "inherits" all the
// fields and methods of our Validator type (including the FieldErrors field).
type snippetCreateForm struct {
    Title               string
    Content             string
    Expires             int
    validator.Validator
}

// Because the Validator type is embedded by the snippetCreateForm struct,
// we can call CheckField() directly on it to execute our validation checks.
form.CheckField(validator.NotBlank(form.Title), "title", "This field cannot be blank")
form.CheckField(validator.MaxChars(form.Title, 100), "title", "This field cannot be more than 100 characters long")
form.CheckField(validator.NotBlank(form.Content), "content", "This field cannot be blank")
form.CheckField(validator.PermittedInt(form.Expires, 1, 7, 365), "expires", "This field must equal 1, 7 or 365")

if !form.Valid() {
    data := app.newTemplateData(r)
    data.Form = form
    app.render(w, http.StatusUnprocessableEntity, "create.tmpl", data)
    return
}

Embedding is doing real work here. snippetCreateForm gains FieldErrors as a field and CheckField, AddFieldError and Valid as methods, so the template still reads .Form.FieldErrors.title and the handler still calls form.Valid() — and any future form can embed the same Validator and get the same API.

8.6 · Automatic form parsing

One more simplification, using a third-party decoder. It is entirely optional; it earns its place when an application has many forms, or one very large one.

Terminalshell
$ go get github.com/go-playground/form/v4@v4
go get: added github.com/go-playground/form/v4 v4.2.0

One decoder for the whole application, created in main() and injected like every other dependency:

File: cmd/web/main.gogo
// Add a formDecoder field to hold a pointer to a form.Decoder instance.
type application struct {
    errorLog      *log.Logger
    infoLog       *log.Logger
    snippets      *models.SnippetModel
    templateCache map[string]*template.Template
    formDecoder   *form.Decoder
}

// Initialize a decoder instance...
formDecoder := form.NewDecoder()

// And add it to the application dependencies.
app := &application{
    errorLog:      errorLog,
    infoLog:       infoLog,
    snippets:      &models.SnippetModel{DB: db},
    templateCache: templateCache,
    formDecoder:   formDecoder,
}

Struct tags map form names to fields, and form:"-" keeps the embedded Validator out of the decoding:

File: cmd/web/handlers.gogo
type snippetCreateForm struct {
    Title               string `form:"title"`
    Content             string `form:"content"`
    Expires             int    `form:"expires"`
    validator.Validator `form:"-"`
}

// Declare a new empty instance of the snippetCreateForm struct.
var form snippetCreateForm

// Call the Decode() method of the form decoder, passing in the current
// request and *a pointer* to our snippetCreateForm struct. This will
// essentially fill our struct with the relevant values from the HTML form.
// If there is a problem, we return a 400 Bad Request response to the client.
err = app.formDecoder.Decode(&form, r.PostForm)
if err != nil {
    app.clientError(w, http.StatusBadRequest)
    return
}

The gain is that type conversion is handled for you: "7" lands in the int field Expires without a strconv.Atoi in sight, and it scales to a form of any size.

But Decode has a trap

Decode() requires a non-nil pointer as its destination. Pass anything else and it returns a form.InvalidDecoderError. That is never the client's fault — it means the application passed the wrong thing — so treating it as a 400 would hide a bug. The book's decodePostForm() helper checks for that one error type and turns it into a panic, which chapter 6's recoverPanic middleware then handles:

File: cmd/web/helpers.gogo
// Create a new decodePostForm() helper method. The second parameter here, dst,
// is the target destination that we want to decode the form data into.
func (app *application) decodePostForm(r *http.Request, dst any) error {
    // Call ParseForm() on the request, in the same way that we did in our
    // createSnippetPost handler.
    err := r.ParseForm()
    if err != nil {
        return err
    }

    // Call Decode() on our decoder instance, passing the target destination as
    // the first parameter.
    err = app.formDecoder.Decode(dst, r.PostForm)
    if err != nil {
        // If we try to use an invalid target destination, the Decode() method
        // will return an error with the type *form.InvalidDecoderError. We use
        // errors.As() to check for this and raise a panic rather than returning
        // the error.
        var invalidDecoderError *form.InvalidDecoderError

        if errors.As(err, &invalidDecoderError) {
            panic(err)
        }

        // For all other errors, we return them as normal.
        return err
    }
    return nil
}

And the final handler — four lines of preparation, four checks, one branch:

File: cmd/web/handlers.go — the finished handlergo
func (app *application) snippetCreatePost(w http.ResponseWriter, r *http.Request) {
    var form snippetCreateForm

    err := app.decodePostForm(r, &form)
    if err != nil {
        app.clientError(w, http.StatusBadRequest)
        return
    }

    form.CheckField(validator.NotBlank(form.Title), "title", "This field cannot be blank")
    form.CheckField(validator.MaxChars(form.Title, 100), "title", "This field cannot be more than 100 characters long")
    form.CheckField(validator.NotBlank(form.Content), "content", "This field cannot be blank")
    form.CheckField(validator.PermittedInt(form.Expires, 1, 7, 365), "expires", "This field must equal 1, 7 or 365")

    if !form.Valid() {
        data := app.newTemplateData(r)
        data.Form = form
        app.render(w, http.StatusUnprocessableEntity, "create.tmpl", data)
        return
    }

    id, err := app.snippets.Insert(form.Title, form.Content, form.Expires)
    if err != nil {
        app.serverError(w, err)
        return
    }

    http.Redirect(w, r, fmt.Sprintf("/snippet/view/%d", id), http.StatusSeeOther)
}

That pattern — decode into a form struct, run the checks, re-render on failure, insert and redirect on success — is what the signup and login forms later in the book reuse verbatim.
