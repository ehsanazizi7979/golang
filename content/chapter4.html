Chapter 4 — Database-driven responses

“Somewhere to store the data”

Chapter 4 gives Snippetbox a memory. It installs MySQL, wires up a connection pool, extracts a reusable models package, and then walks through the three shapes of SQL call — Exec for writes, QueryRow for one row, Query for many — plus transactions and the prepared-statement trade-off.

A note on the live demo. There is no MySQL server in this sandbox, so the demo replaces the database with an in-memory snippets table. Everything else is faithful: the same SQL statements, the same ? placeholder parameters, the same SnippetModel methods, the same models.ErrNoRecord behaviour, and a real Begin/Rollback/Commit cycle. The %+v output below is byte-for-byte the shape the book prints in its screenshots.

4.1 · Setting up MySQL

The chapter creates a UTF-8 database, a snippets table, and seeds it with three haiku. The table is deliberately simple: an auto-incrementing id, a short title, the content, and two timestamps — when the snippet was made and when it expires.

mysql — the schemasql
CREATE DATABASE snippetbox CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE snippetbox;

CREATE TABLE snippets (
    id INTEGER NOT NULL PRIMARY KEY AUTO_INCREMENT,
    title VARCHAR(100) NOT NULL,
    content TEXT NOT NULL,
    created DATETIME NOT NULL,
    expires DATETIME NOT NULL
);

-- Add an index on the created column.
CREATE INDEX idx_snippets_created ON snippets(created);

Three sample records are inserted — two that expire in a year, one that expires in a week (which is useful later, because it lets the queries demonstrate expiry filtering):

mysql — the seed datasql
INSERT INTO snippets (title, content, created, expires) VALUES (
    'An old silent pond',
    'An old silent pond...\nA frog jumps into the pond,\nsplash! Silence again.\n\n– Matsuo Bashō',
    UTC_TIMESTAMP(),
    DATE_ADD(UTC_TIMESTAMP(), INTERVAL 365 DAY)
);

Connections are made as a restricted web user with only the privileges the application needs — never as root:

mysql — a least-privilege usersql
CREATE USER 'web'@'localhost';
GRANT SELECT, INSERT, UPDATE, DELETE ON snippetbox.* TO 'web'@'localhost';
-- Important: Make sure to swap 'pass' with a password of your own choosing.
ALTER USER 'web'@'localhost' IDENTIFIED BY 'pass';

Verifying the permissions. As web, SELECT works and DROP TABLE does not: ERROR 1142 (42000): DROP command denied to user 'web'@'localhost' for table 'snippets'. That is the point of the restricted user.

4.2 · Installing a database driver

Go talks to MySQL through a driver, which translates between database/sql and the database. The book uses go-sql-driver/mysql, pinned to a major version:

Terminalshell
$ go get github.com/go-sql-driver/mysql@v1
go: downloading github.com/go-sql-driver/mysql v1.7.0

The @v1 suffix means “the latest v1.x.x”; any release in that series is compatible. Omitting the suffix takes the newest version regardless of major number, and a full version pins it exactly.

4.4 · Creating a database connection pool

This is the section with the most misunderstood idea in it: sql.Open() does not return a connection. It returns a pool, long-lived, safe for concurrent use, opening connections lazily as needed.

The poolgo
// The sql.Open() function initializes a new sql.DB object, which is essentially a
// pool of database connections.
db, err := sql.Open("mysql", "web:pass@/snippetbox?parseTime=true")
if err != nil {
    ...
}

Because connections are lazy, a successful sql.Open() proves nothing. db.Ping() forces one real connection, so the failure surfaces at start-up rather than on a user's first request:

File: cmd/web/main.gogo
// The openDB() function wraps sql.Open() and returns a sql.DB connection pool
// for a given DSN.
func openDB(dsn string) (*sql.DB, error) {
    db, err := sql.Open("mysql", dsn)
    if err != nil {
        return nil, err
    }

    if err = db.Ping(); err != nil {
        return nil, err
    }

    return db, nil
}

The driver import is prefixed with an underscore — the blank identifier — because main.go never refers to anything in the package directly. It is imported only so its init() can register itself with database/sql. The DSN comes from a new flag, so the database can change per environment:

Flags and the blank importgo
import (
    "database/sql" // New import
    "flag"
    "log"
    "net/http"
    "os"

    _ "github.com/go-sql-driver/mysql" // New import
)

// Define a new command-line flag for the MySQL DSN string.
dsn := flag.String("dsn", "web:pass@/snippetbox?parseTime=true", "MySQL data source name")

Why parseTime=true. Without it the driver returns DATETIME columns as []byte instead of time.Time. With a bad DSN the failure is immediate and explicit: ERROR … main.go:32: Error 1045: Access denied for user 'web'@'localhost' (using password: YES).

The model is then constructed in main() and injected through the application struct, exactly like the loggers in chapter 3:

Wiring the model ingo
type application struct {
    errorLog *log.Logger
    infoLog  *log.Logger
    snippets *models.SnippetModel
}

// Initialize a models.SnippetModel instance and add it to the application
// dependencies.
app := &application{
    errorLog: errorLog,
    infoLog:  infoLog,
    snippets: &models.SnippetModel{DB: db},
}

Why this structure pays off. Handlers stay limited to HTTP concerns; the model is one encapsulated object that can be initialised and passed around; because its actions are methods on a type, it can later be replaced by an interface and mocked in tests; and the database is chosen at runtime by the -dsn flag.

4.6 · Executing SQL statements

Three methods cover every case: DB.Query() for SELECTs returning many rows, DB.QueryRow() for a single row, and DB.Exec() for statements that return no rows. An INSERT is the third kind.

File: internal/models/snippets.go — Insert()go
func (m *SnippetModel) Insert(title string, content string, expires int) (int, error) {
    // Write the SQL statement we want to execute. I've split it over two lines
    // for readability (which is why it's surrounded with backquotes instead
    // of normal double quotes).
    stmt := `INSERT INTO snippets (title, content, created, expires)
    VALUES(?, ?, UTC_TIMESTAMP(), DATE_ADD(UTC_TIMESTAMP(), INTERVAL ? DAY))`

    // Use the Exec() method on the embedded connection pool to execute the
    // statement. The first parameter is the SQL statement, followed by the
    // title, content and expiry values for the placeholder parameters. This
    // method returns a sql.Result type, which contains some basic
    // information about what happened when the statement was executed.
    result, err := m.DB.Exec(stmt, title, content, expires)
    if err != nil {
        return 0, err
    }

    // Use the LastInsertId() method on the result to get the ID of our
    // newly inserted record in the snippets table.
    id, err := result.LastInsertId()
    if err != nil {
        return 0, err
    }

    // The ID returned has the type int64, so we convert it to an int type
    // before returning.
    return int(id), nil
}

The sql.Result gives LastInsertId() (the auto-increment id) and RowsAffected(). Neither is universal — PostgreSQL, for example, has no LastInsertId() — so check your driver. When you don't need the result, discard it with _, err := m.DB.Exec(…).

Called from the handler, it inserts a hard-coded snippet and redirects to it with http.StatusSeeOther (303) — which is why curl -iL follows the redirect and shows both responses:

Placeholder parameters stop SQL injection. DB.Exec() works in three steps: it prepares the statement on the database (parsed and compiled), then sends the values separately, then closes the statement. Because the values arrive after compilation the database treats them as pure data — they cannot change the statement's intent. MySQL, SQL Server and SQLite use ?; PostgreSQL uses $1, $2, $3.

Live: on /db, run the same query with 1 OR 1=1 as a ? parameter and then interpolated into the SQL. The parameterised version returns no rows (it is just an odd id); the interpolated version returns all three — because the value became part of the statement.

4.7 · Single-record SQL queries

Selecting one row follows a different pattern: QueryRow() returns a *sql.Row, and you copy the columns into your struct with Scan(). If there is no row, the error appears at Scan() time as sql.ErrNoRows.

File: internal/models/snippets.go — Get()go
func (m *SnippetModel) Get(id int) (*Snippet, error) {
    // Write the SQL statement we want to execute. Again, I've split it over two
    // lines for readability.
    stmt := `SELECT id, title, content, created, expires FROM snippets
    WHERE expires > UTC_TIMESTAMP() AND id = ?`

    // Use the QueryRow() method on the connection pool to execute our
    // SQL statement, passing in the untrusted id variable as the value for the
    // placeholder parameter. This returns a pointer to a sql.Row object which
    // holds the result from the database.
    row := m.DB.QueryRow(stmt, id)

    // Initialize a pointer to a new zeroed Snippet struct.
    s := &Snippet{}

    // Use row.Scan() to copy the values from each field in sql.Row to the
    // corresponding field in the Snippet struct. Notice that the arguments
    // to row.Scan are *pointers* to the place you want to copy the data into,
    // and the number of arguments must be exactly the same as the number of
    // columns returned by your statement.
    err := row.Scan(&s.ID, &s.Title, &s.Content, &s.Created, &s.Expires)
    if err != nil {
        // If the query returns no rows, then row.Scan() will return a
        // sql.ErrNoRows error. We use the errors.Is() function check for that
        // error specifically, and return our own ErrNoRecord error
        // instead (we'll create this in a moment).
        if errors.Is(err, sql.ErrNoRows) {
            return nil, ErrNoRecord
        } else {
            return nil, err
        }
    }

    // If everything went OK then return the Snippet object.
    return s, nil
}

The model translates the datastore's error into its own, so nothing outside the package depends on MySQL:

File: internal/models/errors.gogo
package models

import (
    "errors"
)

var ErrNoRecord = errors.New("models: no matching record found")
File: cmd/web/handlers.go — snippetView()go
snippet, err := app.snippets.Get(id)
if err != nil {
    if errors.Is(err, models.ErrNoRecord) {
        app.notFound(w)
    } else {
        app.serverError(w, err)
    }
    return
}

// Write the snippet data as a plain-text HTTP response body.
fmt.Fprintf(w, "%+v", snippet)

Additional information. Prefer errors.Is() to ==: since Go 1.13 an error can be wrapped, and a wrapped error is a new value, so == would fail while errors.Is() unwraps first (errors.As() does the same for types). The Get() code can also be shortened, since QueryRow() defers its error until Scan().

4.8 · Multiple-record SQL queries

For many rows the method is Query(), and the resultset must be closed. The pattern is: check the error, defer rows.Close(), loop with rows.Next() and rows.Scan(), then check rows.Err().

File: internal/models/snippets.go — Latest()go
func (m *SnippetModel) Latest() ([]*Snippet, error) {
    // Write the SQL statement we want to execute.
    stmt := `SELECT id, title, content, created, expires FROM snippets
    WHERE expires > UTC_TIMESTAMP() ORDER BY id DESC LIMIT 10`

    // Use the Query() method on the connection pool to execute our
    // SQL statement. This returns a sql.Rows resultset containing the result of
    // our query.
    rows, err := m.DB.Query(stmt)
    if err != nil {
        return nil, err
    }

    // We defer rows.Close() to ensure the sql.Rows resultset is
    // always properly closed before the Latest() method returns. This defer
    // statement should come *after* you check for an error from the Query()
    // method. Otherwise, if Query() returns an error, you'll get a panic
    // trying to close a nil resultset.
    defer rows.Close()

    // Initialize an empty slice to hold the Snippet structs.
    snippets := []*Snippet{}

    for rows.Next() {
        // Create a pointer to a new zeroed Snippet struct.
        s := &Snippet{}

        err = rows.Scan(&s.ID, &s.Title, &s.Content, &s.Created, &s.Expires)
        if err != nil {
            return nil, err
        }

        snippets = append(snippets, s)
    }

    // When the rows.Next() loop has finished we call rows.Err() to retrieve any
    // error that was encountered during the iteration. It's important to
    // call this - don't assume that a successful iteration was completed
    // over the whole resultset.
    if err = rows.Err(); err != nil {
        return nil, err
    }

    return snippets, nil
}

Important. An open resultset keeps its underlying connection open. Forget rows.Close() and a busy server can exhaust every connection in the pool — which is exactly the kind of failure the chapter is trying to inoculate you against.

4.9 · Transactions and other details

Exec(), Query() and QueryRow() may each grab a different connection from the pool — even back-to-back calls. When that matters (locking a table, or applying several statements as one unit), wrap them in a transaction:

The transaction patterngo
func (m *ExampleModel) ExampleTransaction() error {
    // Calling the Begin() method on the connection pool creates a new sql.Tx
    // object, which represents the in-progress database transaction.
    tx, err := m.DB.Begin()
    if err != nil {
        return err
    }

    // Defer a call to tx.Rollback() to ensure it is always called before the
    // function returns. If the transaction succeeds it will be already be
    // committed by the time tx.Rollback() is called, making tx.Rollback() a
    // no-op. Otherwise, in the event of an error, tx.Rollback() will rollback
    // the changes before the function returns.
    defer tx.Rollback()

    // Call Exec() on the transaction, passing in your statement and any
    // parameters. It's important to notice that tx.Exec() is called on the
    // transaction object just created, NOT the connection pool.
    _, err = tx.Exec("INSERT INTO ...")
    if err != nil {
        return err
    }

    _, err = tx.Exec("UPDATE ...")
    if err != nil {
        return err
    }

    // If there are no errors, the statements in the transaction can be committed
    // to the database with the tx.Commit() method.
    err = tx.Commit()
    return err
}

Important. Always call either Rollback() or Commit() before returning. If you don't, the connection stays open and never returns to the pool — the same resource-exhaustion trap as an unclosed resultset. defer tx.Rollback() is the simple way to guarantee it.

Live: /db/transaction runs the pattern with two statements where the second fails, and shows the log: BEGIN → INSERT → ROLLBACK, with the inserted row gone afterwards. That is the all-or-nothing guarantee in action.

Also covered in this chapter. database/sql is a portable interface — MySQL, PostgreSQL and SQLite all work through it, with driver quirks to check — and the code is verbose but non-magical, which is the point. NULL values are awkward to scan (a NULL title fails with unsupported Scan, storing driver.Value type <nil> into type *string); the easy fix is NOT NULL constraints everywhere, as this schema does. And prepared statements (DB.Prepare()) can be reused for complex, frequently-run queries, at the cost of complexity and of statements being re-prepared across pool connections — measure before adopting them.
