The chapter

“In this book we’ll be building a web application called Snippetbox.”

Snippetbox lets people paste and share snippets of text — a bit like Pastebin or GitHub’s Gists. By the end of the book it looks like the screenshot below: a “Create a New Snippet” page with a title field, a content box, a Delete in choice of one year / one week / one day, and a green Publish snippet button.

The application starts off super simple, with just one web page. Then with each chapter it’s built up step-by-step until a user can save and view snippets through the app. That journey covers how to structure a project, routing requests, working with a database, processing forms and displaying dynamic data safely.

Later in the book user accounts are added, and the application is restricted so that only registered users can create snippets — which brings in configuring a HTTPS server, session management, user authentication and middleware.

Figure 1.1 — the finished app

Why show the end first? Everything in chapters 2–15 is a step towards this one form. Keeping the screenshot in mind makes the incremental refactors — a handler, then a servemux, then templates, then a database — feel like progress rather than churn.

Prerequisites — background knowledge

The book is designed for people who are new to Go, but it’s more enjoyable if you have a general understanding of Go’s syntax first. If you find yourself struggling with the syntax, The Little Go Book by Karl Seguin is a fantastic tutorial, and for something more interactive the Tour of Go is the recommendation.

You’re also expected to have a (very) basic understanding of HTML/CSS and SQL, and some familiarity with using a terminal. If you’ve built a web application in any other language before — Ruby, Python, PHP or C# — the book is a good fit.

  • Go syntax basics
  • Basic HTML & CSS
  • Basic SQL
  • Comfortable in a terminal

Prerequisites — Go 1.20

The book is correct for the latest major release of Go (version 1.20), and that’s the version to install if you want to code along. If Go is already installed, check it from the terminal with go version:

Terminalshell
$ go version
go version go1.20 linux/amd64

If you need to upgrade — or install Go from scratch — do it now. The chapter points at these instructions:

Prerequisites — other software

A few other bits of software should be available if you want to follow along fully:

  1. curl — for working with HTTP requests and responses from your terminal. On macOS and Linux it’s usually pre-installed or in your software repositories; otherwise download the latest version.
  2. A web browser with good developer tools — the book uses Firefox, but Chromium, Chrome or Microsoft Edge work just as well.
  3. Your favourite text editor — the chapter ends there, mid-sentence, because any editor will do.

How to read the book

Chapter one also sets the conventions used throughout — worth knowing before you copy a single line.

Code blocks have a silver background; long blocks may replace irrelevant parts with an ellipsis. Most blocks carry a title bar naming the file you’re working on:

File: hello.gogo
package main

... // Indicates that some existing code has been omitted.

func sayHello() {
    fmt.Println("Hello world!")
}

Terminal instructions have a black background and start with a dollar sign. They work on any Unix-based system, macOS and Linux alike; sample output appears in silver beneath the command:

Terminalshell
$ echo "Hello world!"
Hello world!

On Windows, substitute the DOS equivalent or use the normal Windows GUI. Some chapters finish with an additional information section that isn’t needed for the build but is still important — very new Gophers can skip those and circle back later.

Hint from the book: if you’re following along with the application build, use the HTML version of the book rather than the PDF or EPUB. It works in all browsers, and the formatting of code blocks is retained if you want to copy-and-paste code directly.

The chapter’s one piece of code

Strictly, chapter one ships no Go. The very next chapter opens with the project skeleton and the traditional first program, included here because it’s what the live demo is built on:
